# 아키텍처

## 1. 현재 구조

현재 버전은 기존 정적 프로토타입과 React 전환 화면을 함께 유지하며, 실서비스 전환을
위한 NestJS·Prisma API 기반을 추가한 단계입니다. 실제 회원·결제·콘텐츠 API 연결 전까지
기존 화면의 데모 상태는 브라우저에 남아 있습니다.

```text
브라우저
  ├─ index.html       화면 구조와 콘텐츠
  ├─ lecture.html     구독 플랜·강의 CMS·구독내역·플레이어
  ├─ styles.css       디자인 시스템과 반응형 레이아웃
  ├─ script.js        탭, 문제, 모달, 토스트
  ├─ lecture.js       계정 구독·종료·전체영상 권한·진도 데모
  └─ assets/          이미지와 파비콘
          │
          ▼
dev-server.mjs        개발 중 정적 파일 제공

server/
  ├─ NestJS 상태·인증·보호자 연결·공개 강의 API
  ├─ Prisma 회원·세션·보호자 동의·시대·강의·구독·진도·감사로그 모델
  └─ PostgreSQL 마이그레이션과 6개 시대·PRE-01 초기 데이터
```

기존 강의 CMS의 일부 학습자료 데모는 브라우저 `localStorage`에 남아 있습니다. 이메일·OAuth 로그인, 보호자 연결·동의·학생 학습 리포트, 공개 시대·강의 카탈로그, 강의 등록·수정·상태 관리, 구독 주문·토스 결제 승인·웹훅·구독 발급·전액 환불·기간별 관리자 대사와 CSV 내보내기, 구독 기간 기반 접근 판정과 강의 진도, S3 호환 비공개 저장소의 MP4 및 권한 기반 HLS 재생, FFmpeg 자동 HLS 변환 영속 큐, CloudFront 서명 URL 전송 어댑터, 대용량 MP4 비동기 ClamAV 검사와 미완료·교체 영상 자동 정리, 썸네일·문서 격리 검사와 권한 기반 서명 다운로드는 서버 API로 전환됐습니다. OAuth 공급자 통신과 결제 공급자 통신은 `server/src/components`의 재사용 가능한 NestJS 컴포넌트로 분리했습니다.

React 전환을 위해 `package.json`, Vite·TypeScript 설정, `src/`와 `/app.html` 진입점을 추가했습니다. 기존 정적 페이지는 Vite 멀티페이지 빌드에 함께 포함하며 기능 단위 이전이 끝날 때까지 병행합니다. React에는 계정·학생 여행지도·보호자 연결 및 학습 리포트·공개 강의 탐색·계정 구독 경로가 구현됐고 API는 세션 인증, 역할 검사, 보호자 동의, 공개 콘텐츠와 구독 결제를 제공합니다.

## 2. 목표 서비스 구조

MVP에서는 프런트엔드, API 서버, 콘텐츠 저장소를 분리합니다. API는 Node.js 24 LTS,
NestJS, Prisma 기반의 모듈러 모놀리스로 만들고 관리형 PostgreSQL에 연결합니다.

```text
학생·학부모·지도자 브라우저
             │
             ▼
반응형 웹 애플리케이션
  ├─ 공개 콘텐츠
  ├─ 강의 플레이어·사용자 착수형 바둑미션
  ├─ 학생/학부모 대시보드
  └─ 지도자 반 관리
             │ HTTPS / JSON
             ▼
애플리케이션 API
  ├─ 인증·권한
  ├─ 강의·문제은행·바둑 규칙 엔진·미션·진도
  ├─ 보상·컬렉션
  ├─ 반·과제·리포트
  ├─ 상담·알림
  └─ 주문·결제
      │        │         │
      ▼        ▼         ▼
 PostgreSQL   비공개 객체 저장소   외부 서비스
             영상·PDF    결제·문자·이메일
```

개발·배포 기준은 [구현·개발·배포 제안서](./IMPLEMENTATION_PROPOSAL.md)를 따릅니다.

## 3. 권장 프런트엔드 모듈

실서비스 전환 시 단일 `script.js`를 다음 경계로 분리합니다.

```text
src/
├─ app/                 # 라우팅, 전역 설정, 인증 초기화
├─ components/          # 버튼, 모달, 카드, 진행 표시
├─ features/
│  ├─ auth/             # 로그인, 회원가입, 역할 선택
│  ├─ journey/          # 시대 지도와 강의 목록
│  ├─ lesson/           # 영상, 연결 문제, 역사 퀴즈
│  ├─ baduk-mission/    # 9·13·19줄 판, 문제 카드·확대창, 착수, 규칙, 수순
│  ├─ problem-author/   # 관리자 초기 판·정답 트리·힌트 입력기와 검수
│  ├─ components/       # 재사용 OAuth·결제 계약과 공급자 어댑터
│  ├─ subscription/     # 구독 플랜, 결제, 계정 구독, 종료 권한
│  ├─ progress/         # 진도, 별, 배지, 유물 카드
│  ├─ classroom/        # 반, 과제, 게시물형 수업 패키지
│  ├─ store/            # 교재, 장바구니, 주문
│  └─ community/        # 공지, FAQ, 게시물
├─ services/            # API 클라이언트, 오류 처리
├─ styles/              # 토큰, 기본 스타일, 컴포넌트
└─ types/               # API와 도메인 타입
```

실서비스 프런트엔드는 React + TypeScript, Vite, React Router, TanStack Query를 기준으로 개발합니다. 바둑판은 SVG 기반 React 컴포넌트로 만들고 규칙 코어는 프레임워크 독립 TypeScript 모듈로 분리합니다. 세부 전환 기준은 [React 프런트엔드 기술 스택](./FRONTEND_STACK.md)을 따릅니다.

## 5. 주요 데이터 흐름

### 학생 강의 완료

1. 학생이 강의를 선택합니다.
2. 서버가 강의의 `isFreeSample` 또는 계정 구독의 `startsAt`과 `endsAt`을 검사합니다.
3. 무료 샘플이거나 구독 권한이 유효하면 강의 내용과 서명 재생 URL, 현재 진도를 반환합니다.
4. 구독이 종료된 경우 재생을 차단하고 새 구독 플랜을 안내합니다.
5. 영상 또는 카드뉴스 열람 상태를 기록합니다.
6. 사용자가 바둑판에 직접 착수하고 상대 자동 응수 수순을 진행한 뒤 역사 퀴즈 답안을 제출합니다.
7. 서버가 점수와 해설을 반환합니다.
8. 완료 조건 충족 시 별·배지·유물 카드를 지급합니다.
9. 다음 강의를 개방하고 대시보드 요약을 갱신합니다.

### 사용자 착수형 바둑미션 진행

```text
과정·권·강 선택
  → 문제 카드 목록
  → 카드 클릭
  → PC 확대 모달 또는 모바일 전체화면 열기
  → 구독·무료 샘플 권한 확인
  → 초기 판과 마지막 확정 수순 조회
  → 사용자 미확정 착수
  → 클라이언트 기본 규칙 검사
  → 정답 확인
  → 서버 최종 판정·자동채점
      ├─ 불법: 이유 표시, 차례 유지
      ├─ 오답: 교육 피드백, 체크포인트 재도전
      ├─ 허용: 수순 계속, 점수 정책 적용
      └─ 정답: 돌 확정, 상대 자동 응수
  → 성공 조건 검사
      ├─ 진행 중: 다음 사용자 차례
      └─ 완료: 정답·시도·시간·힌트·점수와 진도·보상 확정
```

클라이언트의 규칙 엔진은 즉시 피드백과 화면 렌더링을 담당하고, 서버 엔진은 수순·완료·점수·보상의 최종 판정을 담당합니다. 카드형·모달·전체화면·수업 화면은 하나의 `BadukProblemPlayer`를 재사용합니다. 상세 구조는 [사용자 착수형 바둑문제·바둑미션 게임 기획](./BADUK_MISSION_GAME.md)을 따릅니다.

### 교재 QR 진입

1. 사용자가 교재의 QR을 스캔합니다.
2. `/qr/{code}`에서 코드 유효성과 이용 권한을 확인합니다.
3. 로그인하지 않은 사용자는 로그인 후 원래 강의로 복귀합니다.
4. 권한이 있으면 연결된 강의를 바로 엽니다.
5. 미등록 코드에는 등록 또는 구매 안내를 제공합니다.

### 지도자 과제 배포

1. 지도자가 반과 강의를 선택합니다.
2. 마감일과 목표 점수를 설정합니다.
3. 과제 생성 후 학생 계정에 알림을 발송합니다.
4. 학생 결과를 반 단위로 집계합니다.
5. 지도자는 오답 유형과 미완료 학생을 확인합니다.

### 지도자 수업도우미 실행

1. 지도자가 수업도우미 게시판에서 강의 패키지 하나를 선택합니다.
2. 서버가 인증 지도자 역할과 개인 이용권 또는 기관 라이선스를 확인합니다.
3. 상세 화면이 도입, 개념 설명, 문제풀이, 역사 퀴즈, 마무리 순서를 표시합니다.
4. 같은 게시물에 연결된 영상, PPT, 활동지, 퀴즈, 미션, 정답해설, 진행가이드를 반환합니다.
5. 지도자는 별도의 자료 검색 없이 화면 순서대로 25~30분 수업을 진행합니다.

## 7. 비기능 요구사항

- 모바일 우선 반응형 지원
- 개인정보와 미성년자 계정 보호
- 강의 진도 요청의 중복 처리 방지
- 착수 요청 멱등 처리와 판 상태 동시성 제어
- 9·13·19줄 확대·축소 시 렌더 좌표와 입력 좌표의 동일 변환 보장
- 영상과 이미지는 비공개 객체 저장소에서 권한을 확인해 제공합니다. HLS 재생목록 프록시와 세그먼트별 단기 서명을 적용했고, 미디어 전송 계층은 CloudFront 서명 URL 또는 S3 직접 서명 URL 폴백을 선택합니다. 실제 배포의 CloudFront 배포·OAC·신뢰 키 그룹·캐시 정책은 운영 계정에서 설정합니다.
- 주요 페이지 Core Web Vitals 모니터링
- 관리자 콘텐츠 변경 이력 보관
- 오류 로그에 비밀번호, 토큰, 전화번호를 기록하지 않음
- 일일 데이터 백업과 복구 절차 마련
