# 사용자 착수형 바둑문제·바둑미션 게임 기획

## 1. 문서 목적과 반영 기준

이 문서는 사용자가 바둑판에 직접 돌을 놓아 문제를 푸는 게임과, 관리자가 문제를 제작·검수·공개하는 CMS를 정의합니다. 화면에서 사용하는 서비스 명칭은 `바둑미션`, 데이터와 관리자 화면의 콘텐츠 명칭은 `바둑문제`로 통일합니다.

기획 반영 기준:

- [바둑문제 입력기·유저용 문제풀이 원본 기획서](./바둑문제_입력기_유저용_기획서_플로차트_확대창기능추가.pptx)
- 9줄·13줄·19줄 통합 운영
- 관리자 문제 입력기, 수순 트리, 자동채점, 학습기록, 문제은행
- 문제 카드에서 여는 PC 확대 모달과 모바일 전체화면 풀이
- 기존 홈페이지의 강의, 시대지도, 지도자 수업도우미, 계정 구독 정책

이 문서는 기존의 `9×9 우선, 13×13·19×19 후속` 가정을 대체합니다. 9줄·13줄·19줄 렌더링과 문제 데이터 호환은 1차 MVP 필수 범위입니다. 범용 AI 대국과 자유대국은 포함하지 않습니다.

## 2. 핵심 원칙

- 문제는 이미지가 아니라 재편집·자동채점이 가능한 바둑판 좌표 데이터로 저장합니다.
- 한 문제는 `초기 판 상태 + 누구 차례 + 정답 수순 트리 + 허용 변화도 + 힌트 + 해설 + 메타데이터`로 구성합니다.
- 사용자는 A/B/C 버튼이 아니라 바둑판 교차점에 직접 착수합니다.
- 합법 수 검사는 바둑 규칙 엔진이, 정답 여부는 문제의 수순 트리가 판정합니다.
- 상대 응수는 관리자가 등록한 수순 트리에서 자동 진행합니다.
- 작은 문제 카드와 확대창은 서로 다른 게임을 만들지 않고 동일한 문제풀이 컴포넌트를 다른 표시 모드로 렌더링합니다.
- 결과는 정답 여부뿐 아니라 시도 횟수, 풀이시간, 힌트 사용, 획득점수까지 학습기록으로 저장합니다.

## 3. 서비스 연결 위치와 접근권한

| 진입 위치 | 용도 |
|---|---|
| 강의 플레이어 `판 위의 미션` | 강의 개념 확인, 반복 훈련, 도전 문제 |
| 강의 페이지 문제 카드 | 썸네일 확인 후 확대 문제풀이 창 실행 |
| 시대 여행 지도 | 시대·강의에 연결된 대표 미션 실행 |
| 학생 대시보드 | 이어하기, 오답노트, 즐겨찾기, 추천 문제 |
| 지도자 수업도우미 | 수업 패키지 안에서 대형 문제풀이 화면 실행 |
| 무료 체험 | `isFreeSample = true`인 공개 샘플 미션 실행 |

권한 원칙:

- 일반 공개 미션은 로그인과 유효한 계정 구독이 필요합니다.
- `published`이면서 `isFreeSample = true`인 미션은 비회원과 비구독자도 실행할 수 있습니다.
- 비회원 샘플 결과는 현재 브라우저에만 임시 저장하며 계정 진도, 오답노트, 보상에는 합산하지 않습니다.
- 운영자와 관리자는 작성·검수용 미리보기가 가능합니다.
- 지도자 수업도우미에서 실행하는 미션은 지도자 역할과 기관 라이선스 정책을 서버에서 확인합니다.

권장 경로:

```text
/missions                              문제 목록
/mission.html?missionId={missionId}    직접 문제풀이 진입
/admin/missions                        관리자 문제 관리
/admin/missions/{missionId}/edit       문제 입력기
```

## 4. 교육과정과 문제은행

### 4.1 교육과정 구조

| 과정 | 권·강 구성 | 권장 판 | 주요 내용 |
|---|---:|---|---|
| 입문 1~6권 | 6권 × 8강 = 48강 | 9줄 중심 | 규칙, 따내기, 활로, 연결, 기초 사활 |
| 기초 1~6권 | 6권 × 8강 = 48강 | 9줄 → 13줄 | 사활, 수읽기, 맥, 연결·끊기 |
| 기본 1~6권 | 6권 × 8강 = 48강 | 13줄 → 19줄 | 사활, 맥, 포석, 정석, 실전 응용 |

총 18권, 144강을 기준으로 합니다. 판 크기는 과정의 기본값일 뿐이며 관리자가 문제별로 9·13·19줄 중 하나를 확정합니다.

### 4.2 강의별 권장 문제 구성

```text
개념 확인 3문제 + 반복 훈련 5문제 + 도전 문제 2문제 = 강의당 약 10문제
```

144강 전체 적용 시 약 1,440문제 규모의 문제은행으로 확장할 수 있습니다. 각 문제에는 `과정 → 권 → 강 → 문제군 → 정렬 순서`를 저장하여 강의, 교재, 과제에서 같은 원본 문제를 재사용합니다.

## 5. 문제 유형과 판정 범위

| 유형 | 코드 | 완료 예시 |
|---|---|---|
| 가장 좋은 한 수 | `best_move` | 허용된 정답 좌표에 착수 |
| 따내기 | `capture` | 목표 상대 그룹 제거 |
| 돌 살리기 | `save_stones` | 지정 생존 조건 또는 두 집 달성 |
| 연결 | `connect` | 두 목표 그룹 연결 |
| 끊기 | `cut` | 상대 목표 그룹 분리 |
| 사활 | `life_and_death` | 지정 수순의 성공 노드 도달 |
| 수읽기·맥 | `reading` | 여러 수의 정답 수순 완료 |
| 포석·실전 | `opening` | 허용 변화도 안에서 목표 수순 완료 |
| 단계 수순 | `guided_sequence` | 사용자 수와 상대 응수를 반복해 성공 노드 도달 |

지원 범위:

- 9줄·13줄·19줄 바둑판
- 한 수 문제와 여러 수 문제
- 흑 선수 또는 백 선수
- 단일 정답, 복수 정답, 허용 수, 금지 수순, 상대 응수, 분기 변화도
- 차례, 판 밖, 착점 중복, 따냄, 자충, 패 판정
- 목표 돌 따내기, 살리기, 연결, 끊기, 지정 수순 완료

MVP는 교육용 수순 트리 기반 게임입니다. 자유대국, 실시간 사용자 대국, 범용 AI 상대는 별도 제품 범위로 둡니다.

## 6. 관리자용 바둑문제 입력기

입력기는 한 화면 안에서 다음 순서를 탭 또는 단계 패널로 제공합니다.

```text
기본정보 → 판 입력 → 정답 수순 → 힌트·해설 → 미리보기 → 검수 → 게시
```

### 6.1 기본정보

- 문제 제목과 문제 지시문
- 과정: 입문·기초·기본
- 권: 1~6
- 강: 1~8
- 문제군: 개념 확인·반복 훈련·도전
- 카테고리: 사활·수읽기·맥·포석 등
- 난이도와 목록 정렬 순서
- 배점과 제한시간
- 연결 시대, 교재 페이지, 강의영상 ID, 역사콘텐츠 ID

### 6.2 바둑판 편집기

- 판 크기: 9줄·13줄·19줄 즉시 전환
- 편집 도구: 흑돌, 백돌, 삭제, 전체 초기화
- 착수 차례: 흑 또는 백
- 좌표 표시 켜기·끄기
- 실행취소·다시실행
- 초기 문제도 자동 임시저장
- 화면 크기에 맞춘 자동 확대와 PC·모바일 미리보기

판 크기를 변경하면 기존 돌 좌표가 새 판 범위를 벗어나는지 검사합니다. 범위를 벗어나는 돌이 있으면 자동 삭제하지 않고 변경을 중단한 뒤 충돌 좌표를 안내합니다.

### 6.3 정답 수순 편집기

- 한 수 또는 여러 수의 정답 수순 등록
- 사용자 착수와 상대 응수를 노드 단위로 등록
- 복수 정답 분기 추가
- 허용 변화도 추가
- 금지 수순과 전용 피드백 등록
- 분기 복제·삭제, 수순 순서 변경
- 현재 노드부터 직접 실행 테스트
- 성공·실패·계속 진행 노드 지정

정답은 좌표 배열 한 개가 아니라 분기형 `solutionTree`로 저장합니다. 각 노드는 착수 주체, 색상, 좌표, 판정, 다음 노드, 자동 응수 여부를 가집니다.

### 6.4 힌트·해설과 공개

- 힌트 사용 여부와 최대 단계
- 개념 힌트, 영역 힌트, 좌표 힌트
- 정답 해설과 오답·금지 수순별 설명
- 힌트 사용 시 감점 정책
- `isFreeSample` 무료 공개 여부
- `draft`, `pending_review`, `scheduled`, `published`, `archived` 상태
- 예약 공개시각
- 임시저장, 미리보기, 검수 요청, 게시

### 6.5 공개 전 자동검수

- 판 크기와 모든 좌표 범위 일치
- 초기 판의 돌 중복 없음
- 착수 차례와 수순 노드의 색상 일치
- 모든 정답·변화도 수순의 합법성
- 최소 한 개 이상의 성공 경로 존재
- 도달 불가능한 노드와 무한 반복 없음
- 해설, 필수 힌트, 강의·교재 연결 누락 확인
- 9·13·19줄별 PC·모바일 표시 확인
- 확대창에서 착수 좌표와 실제 교차점 일치

## 7. 좌표와 문제 데이터 규칙

### 7.1 좌표

- 내부 좌표는 좌상단을 `(0, 0)`으로 하는 정수 `x`, `y`를 사용합니다.
- 유효 범위는 `0 <= x, y < boardSize`입니다.
- 화면 좌표 열 문자는 바둑 관례에 따라 `I`를 제외한 `A~T`를 사용합니다.
- SGF 좌표 변환과 화면 좌표 변환은 공통 게임 엔진 한 곳에서 처리합니다.
- 데이터베이스의 원본은 좌표 배열이며 SGF는 가져오기·내보내기용 보조 형식으로 사용합니다.

### 7.2 수순 트리 예시

```json
{
  "rootNodeId": "n0",
  "nodes": {
    "n0": {
      "actor": "player",
      "acceptedMoves": [
        { "x": 3, "y": 4, "result": "correct", "nextNodeId": "n1" },
        { "x": 4, "y": 4, "result": "acceptable", "nextNodeId": "n2" }
      ],
      "forbiddenMoves": [
        { "x": 2, "y": 4, "feedbackId": "fb_cut_failure" }
      ]
    },
    "n1": {
      "actor": "opponent",
      "move": { "color": "white", "x": 4, "y": 5 },
      "nextNodeId": "n3"
    },
    "n3": { "terminal": "success" }
  }
}
```

정답 수순 전체는 관리자 API에서만 반환합니다. 사용자 문제 로드 응답에는 현재 노드에서 필요한 판정 정보도 직접 노출하지 않고 서버가 착수 요청을 판정합니다.

## 8. 유저용 문제 목록과 카드

문제 목록은 과정, 권, 강을 먼저 선택하고 필요한 경우 판 크기, 카테고리, 난이도, 풀이 상태로 필터링합니다.

문제 카드 표시 항목:

- 문제 제목
- 과정·권·강과 문제군
- 난이도와 9·13·19줄 배지
- 초기 판 썸네일
- 미풀이·진행 중·정답·오답 상태
- 무료 샘플 또는 구독 전용 표시
- `시작하기`, `이어하기`, `다시 풀기` 버튼

카드의 썸네일은 별도 정답 이미지가 아니라 초기 판 좌표로 생성합니다. 카드 클릭 또는 시작 버튼을 누르면 같은 문제 ID로 확대 문제풀이 창을 엽니다.

## 9. 확대 문제풀이 창

### 9.1 표시 방식

| 환경 | 표시 방식 |
|---|---|
| PC·태블릿 가로 | 화면 중앙의 큰 모달, 바둑판과 풀이 패널 2열 |
| 모바일·태블릿 세로 | 전체화면 페이지 또는 전체화면 다이얼로그 |
| 지도자 수업 화면 | 전체화면 우선, 큰 바둑판과 최소 조작 패널 |

단순 이미지를 확대하지 않고 기존 `BadukProblemPlayer` 컴포넌트를 `modal`, `fullscreen`, `embedded` 모드로 재사용합니다. 모드를 바꾸어도 `attemptId`, 판 상태, 수순, 타이머, 힌트 기록은 유지합니다.

### 9.2 화면 구성

상단:

- 문제 제목, 난이도, 판 크기
- 과정·권·강과 현재 문제 번호
- 흑·백 중 사용자 색상과 현재 차례
- 경과시간 또는 제한시간
- 닫기, 전체화면 전환

바둑판:

- 9·13·19줄 자동 크기 조정
- 초기 흑·백돌, 마지막 확정 수, 현재 착수 후보 표시
- 좌표 표시 켜기·끄기
- 확대·축소와 화면 맞춤
- 따낸 돌과 상대 자동 응수 애니메이션
- 힌트 영역과 후보 좌표 표시

풀이 패널:

- 문제 지시문과 목표
- 수순 기록과 잡은 돌 수
- 힌트 보기
- 현재 착수 되돌리기
- 처음부터 다시 또는 체크포인트 재도전
- `정답 확인`
- 이전 문제·다음 문제

### 9.3 확대·축소 원칙

- 확대는 브라우저 전체 페이지가 아니라 바둑판 렌더 영역의 배율을 조정합니다.
- 확대 후에도 돌과 교차점의 히트 영역이 같은 좌표 변환을 사용해야 합니다.
- 최소·최대 배율을 두고 `화면 맞춤`으로 즉시 복귀할 수 있게 합니다.
- 모바일의 두 손가락 확대와 PC의 `+`, `-`, `0` 키를 지원합니다.
- 19줄에서도 최소 터치 목표 크기가 부족하면 바둑판을 스크롤 가능한 확대 상태로 전환합니다.

### 9.4 닫기와 접근성

- 닫기 버튼, 브라우저 뒤로가기, `Escape`로 닫을 수 있습니다.
- 모달이 열리면 포커스를 제목 또는 바둑판 시작점으로 옮기고 `Tab` 포커스를 모달 안에 가둡니다.
- 닫은 뒤에는 실행한 문제 카드로 포커스를 되돌립니다.
- 화면 읽기 도구에 현재 좌표, 돌 색상, 차례, 판정 결과를 알립니다.
- 키보드는 방향키로 교차점 이동, `Enter`·`Space`로 착수, `Ctrl+Z`로 현재 미확정 착수 취소를 지원합니다.

## 10. 착수와 자동채점 흐름

착수는 `미확정 착수`와 `서버 확정 착수`를 구분합니다.

1. 사용자 차례에 교차점을 클릭·터치·키보드로 선택합니다.
2. 클라이언트가 판 밖, 중복 착점, 자충 등 명백한 불법 수를 즉시 차단합니다.
3. 합법 후보는 `pendingMove`로 판 위에 표시합니다.
4. 사용자는 `현재 착수 되돌리기`로 후보를 취소하거나 `정답 확인`으로 제출합니다.
5. 제출 중에는 입력을 잠그고 서버가 규칙과 수순 트리를 최종 판정합니다.
6. 정답·허용 수이면 사용자 돌을 확정하고 등록된 상대 응수를 자동 재생합니다.
7. 오답이면 틀린 착수와 이유를 표시하고 설정에 따라 재도전 또는 힌트를 제공합니다.
8. 성공 노드에 도달하면 점수, 시간, 시도 횟수, 힌트 사용을 저장하고 해설과 다음 문제를 표시합니다.

```text
문제 목록
  → 문제 카드 클릭
  → 확대창 열림
  → 초기 판·기존 시도 로드
  → 사용자 착수 후보
  → 정답 확인
  → 서버 자동채점
      ├─ 불법: 착수 취소, 이유 표시
      ├─ 오답: 결과 기록 → 재도전 또는 힌트
      ├─ 허용: 수순 계속, 감점 여부 적용
      └─ 정답: 상대 자동 응수 → 다음 사용자 차례
  → 완료?
      ├─ 아니오: 다음 착수
      └─ 예: 결과·해설·점수 저장 → 다음 문제 또는 복습
```

`정답 확인`은 서버 제출 버튼입니다. 단순히 착점한 순간에 정답 수순을 확정하지 않으므로 사용자는 미확정 착수를 한 번 되돌릴 수 있습니다. 이미 서버에서 확정한 과거 수순은 임의로 무르지 않고 `체크포인트 재도전` 또는 `처음부터 다시`를 사용합니다.

## 11. 게임 상태

```text
closed
  → loading
  → ready
  → player_turn
  → pending_move
  → validating_move
      ├─ retry
      ├─ opponent_turn → player_turn
      └─ success | failed
  → paused | closed
```

| 상태 | 의미 |
|---|---|
| `closed` | 카드만 보이고 확대창은 닫힘 |
| `loading` | 문제·진행 기록 로딩 |
| `ready` | 초기 판과 지시문 표시 완료 |
| `player_turn` | 사용자 착수 가능 |
| `pending_move` | 사용자가 둔 미확정 후보가 있음 |
| `validating_move` | 서버 자동채점 중, 입력 잠금 |
| `opponent_turn` | 상대 자동 응수 재생 중 |
| `retry` | 오답 피드백 후 재도전 대기 |
| `paused` | 이탈 또는 네트워크 중단 |
| `success` | 정답 수순 완료와 결과 확정 |
| `failed` | 제한시간 또는 재도전 횟수 소진 |

## 12. 정답·오답·힌트·점수

판정 유형:

- `correct`: 대표 정답 수순
- `acceptable`: 목표는 달성하지만 대표 정답은 아닌 허용 수순
- `incorrect`: 규칙상 가능하지만 문제 목표를 달성하지 못하는 수
- `forbidden`: 관리자가 별도 설명을 등록한 금지 수순
- `illegal`: 바둑 규칙상 둘 수 없는 수

오답 피드백은 다음 정보를 제공합니다.

```text
왜 실패했는지 → 상대가 어떻게 응수하는지 → 복습할 개념 → 재시작 위치
```

힌트 단계:

1. 개념 힌트: 핵심 개념 안내
2. 영역 힌트: 첫 수가 있는 범위 강조
3. 좌표 힌트: 후보 교차점 표시

점수는 문제별 기본 배점, 오답 횟수, 힌트 단계, 제한시간 초과 여부를 서버에서 계산합니다. 감점식은 운영 설정값으로 관리하고 브라우저 계산을 신뢰하지 않습니다. 힌트를 사용해도 완료는 가능하지만 학습기록에 사용 단계가 남습니다.

## 13. 학습기록과 복습 루프

로그인 사용자는 다음 항목을 저장합니다.

- 정답 여부와 최종 상태
- 시도 횟수와 오답 착수 수
- 시작·마지막 활동·완료시각과 실제 풀이시간
- 힌트 사용 단계와 사용 횟수
- 획득점수와 최고점수
- 마지막 확정 수순과 이어하기 상태
- 과정·권·강·문제군 기준 집계

오답노트 저장 조건:

- 한 번 이상 `incorrect` 또는 `forbidden` 판정을 받은 문제
- 실패 상태로 종료한 문제
- 운영 정책상 복습 대상으로 지정한 문제

다시 풀어 정답을 맞혀도 과거 시도는 삭제하지 않습니다. 오답노트에는 `복습 완료` 상태를 추가하고 최근 결과와 최고 결과를 함께 표시합니다. 문제 난이도 보정과 개인별 추천은 원본 문제의 집계 통계를 사용하되 3차 고도화 범위로 둡니다.

## 18. 서버 판정·동시성·보안

- 클라이언트 판정은 빠른 화면 피드백용이며 최종 결과와 점수는 서버가 결정합니다.
- 서버는 `attemptId`, 미션 버전, 예상 수번호, 현재 판 해시를 검사합니다.
- `clientMoveId`에 고유 제약을 두어 연속 클릭과 네트워크 재시도에도 같은 수가 중복 처리되지 않게 합니다.
- 정답 수순 전체를 사용자 API와 HTML에 노출하지 않습니다.
- 완료 보상은 서버에서 성공 상태가 확정된 시도에 한 번만 지급합니다.
- 공개 문제 수정 시 버전을 올리고 진행 중인 시도는 시작 버전을 유지합니다.
- 로그인 사용자의 확정 판, 수순, 힌트, 오답 수는 제출할 때마다 저장합니다.
- 네트워크 오류 시 미확정 돌을 확정 표시하지 않고 재시도할 수 있게 합니다.
- 여러 기기의 동일 시도 충돌은 먼저 확정된 수만 인정하고 최신 판을 다시 불러옵니다.
