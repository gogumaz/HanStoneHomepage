  - 운영 배포 검증은 스키마 2·인수 `releaseId`와 전체 정규 필드의 `evidenceSha256`을 기록하고, 민감 입력 없이 표본 번호·지연시간·liveness·readiness·후보 일치 여부를 `probes`로 보관함. closeout·최종화·롤백 리허설이 기대 릴리스와 digest를 대조하고 표본 수와 p50/p95/p99/max 및 임계값을 다시 계산하며, 정규 시작→완료 순서와 웹 `checkedAt`·전체 `completedAt` 동일성까지 검사해 다른 릴리스 혼입·집계·시각 변조를 차단함.
  - HTTPS 증빙은 스키마 3, 메일·법무 결합 증빙은 스키마 2로 `releaseId`를 정규 입력과 digest에 결합함. HTTPS 생성 단계가 배포 보고서의 릴리스 ID를 직접 대조하고 closeout·최종화가 세 보조 증빙과 인수 릴리스의 동일성을 재검증해, 자체 digest를 다시 만든 다른 릴리스 증빙의 혼입도 차단함.
